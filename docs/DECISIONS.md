| D6-fn | The `function` contract is the one exception to rule D6 ("never a float"). What: `AnswerContract::Function` compares the key and the learner formula as `f64` values at 8 fixed sample points of each variable interval (default 1/4 to 11/4; fractions 1/16, 3/16, …, 15/16). Why: exact equivalence of elementary functions is not decidable, and `kind: exact` gives "wrong" to a correct answer in a different form (`sec(x)^2` against `1/cos(x)^2`, partial fractions, log laws, `+ C`). Tolerance: `\|a - b\| <= 1e-9 * max(1, \|a\|)` at each point where the key is finite; with `up_to_constant`, `max(d) - min(d) <= 1e-9 * max(1, max\|a\|)` for `d = a - b`. No random source and no clock: one input gives one verdict on one platform `libm`. This variant only: each other contract and `cadus_core::answer::check` stay exact. Rules at authoring time (`validate`, `validate_expected`, thus the loader, `check_keys` and `content_check`): (1) a key that is finite at fewer than 6 of the 8 points is refused; `grade` also gives "wrong" for such a key as the last defense. (2) A key with the name `log` or with the notation `1e-5` is refused (freeze pack D28: the evaluator reads `log` as `ln`, the curriculum reads it as base 10, and the parser reads `1e-5` as `1*e - 5`). (3) A domain that puts a sample point of a variable nearer to 0 than 1/100 is refused for each key: a cancellation key such as `(1 - cos(x))/x^2` loses its digits there, and an equal formula got "wrong" on the domain 1e-8 to 1e-7. (4) An unordered `list` with a `function` member is refused, because that list compares canonical forms. Known limits: (a) a pole at an irrational point is finite in `f64` (`cos(pi/2)` is 6.1e-17), so `1/cos(pi/2) + x` is an accepted key; (b) with `up_to_constant` the rule must hold two times, with each constant name (`C`, `c`, `K`, `k`) at 0 and again at 1 (freeze pack D34), so the learner term `C*x` gives "wrong"; the learner answer `ln(C*x)` for the key `ln(x) + C` is not finite with the constant at 0 and gets "wrong"; (c) the parser refuses `2^x`, `x^x` and `x^2.5` (the exponent must be a whole number or a literal fraction), so an exponential key must use `e^(..)`; (d) two different formulas that agree at the 8 points to 1e-9 get "correct"; no such pair of elementary formulas is known for the default domain. | 2026-09-20 | Lane B4b of the finish flow; `FLOW/spec/rust-api.md` section 2. `crates/core/src/answer/contract/function.rs` (specification, key validation, grade), `crates/core/src/answer/evalf.rs` (lane B4a, the evaluator). Tests: `crates/core/tests/answer_function.rs`, `answer_function_grade.rs`. The `check_keys` mutant of this kind is `2*(E) + v` (`crates/check_keys/src/mutate.rs::mutant_for`), because the `+1` mutant stays correct with `up_to_constant`. |
