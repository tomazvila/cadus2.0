# M1 — Curriculum arena and loader, lint port, parity

Requirement IDs: D1, D2, C5. Spec: `docs/reference/curriculum-1.0-spec.md`.
Oracle: `scripts/oracle/dump_curriculum_1_0.py` (1.0 Python). The curriculum tree is
copied into `curriculum/` (C5: content under git review).

## Fixed decisions (orchestrator)

- All M1 code lives in `cadus-core` (R3). `serde_yaml` (or `serde_yml`) joins the core
  dependency list; the purity test literal changes with it. No network, DB, or LLM.
- Persisted ids are strings; in-flight ids are `TopicIdx(u32)` / `(TopicIdx, KpIdx)`
  (D2). Conversion lives in one module.
- The arena is immutable after load and shared through `Arc<Curriculum>` (D1):
  topics in a `Vec` in load order, string ids interned, prerequisite DAG as CSR in
  both directions, encompassing maps in both directions with the 1.0 asymmetry,
  topological order precomputed (Kahn, min-heap on load index).
- `curriculum_hash` = SHA-256 of the canonical dump (semantic). Literal for the
  checked-in tree: `f121f9baf73f29e89679a3304c5405352f0ff47f163a0140bd0e92102a0a8b9e`.
- Loading tolerates graph-stage lint codes the way 1.0 does; only parse-stage fatal
  findings stop a load.
