# M4 — Serving pool, template instantiation, anti-repeat, L1/L2 benchmarks

Requirement IDs: A1, A5, A6, A7, D5, D-S4, D-S5, D-O1, D-O4, L1, L2, C6, T1, V2.
Spec: `docs/reference/serving-1.0-spec.md` (the 1.0 template document, the 28-check gate
with its literal messages, instantiation, anti-repeat, the FAKE-engine rotation, the serve
path, traps, pinned literals, the benchmark design).

## Fixed decisions (orchestrator)

- Template body (`content_store.body`, kind `template`): the 2.0 shape of spec §2.3 —
  `v`, `topic_id`, `answer_kind` (numeric|expression only, V2), `statement` with `{name}`
  holes and doubled literal braces, `params` (int, choice, rational domains),
  `constraints` (the spec §2.3 constraint language: eq/ne/lt/le/gt/ge/divides/coprime/
  carries over terms built from params, literals, add/sub/mul/abs/mod/digit_sum),
  `answer_expr`, `solution_sketch`, `hints` (≥ 1 rung; no rung names the answer),
  `distractors` (optional), `samples` (kept in the body), `space_size` (the satisfying
  count, exact under 4,096 tuples, else estimated with the sample count recorded).
- One grammar (spec §3.4 option a): `answer_expr` parses with the M2 parser plus an
  evaluation-only function set (`abs`, `sqrt`, `gcd`, `lcm`, `floor`, `ceiling`, `min`,
  `max`, `factorial`, `binomial`) evaluated exactly on rationals and erased before the
  answer string exists; the rendered answer must canonicalize without `Undecidable`.
  No SymPy, no textual substitution, no floats (D6).
- Hash: ONE function, `cadus_core::problem_text_hash` from M3 (`sha1(utf8)[:12]`, no
  normalization) — the M3 parity streams carry those digests. `instance_hash` is that hash
  of the rendered statement.
- RNG: `ChaCha8Rng` seeded per refill batch with a recorded `u64`; the seed and the drawn
  bindings are stored inside `serving_pool.problem`. Bounded integer draws, never `% range`.
- Anti-repeat (D5): a ring of 20 instance hashes per `(user, topic)` plus a per-task
  memory of 12 statement hashes, both in the D-S6 state document; the database unique
  index `(user_id, kp_id, instance_hash)` is the pool invariant. Serve pops at most 8
  candidates with `FOR UPDATE SKIP LOCKED`, skips ring hits, serves the last candidate on
  exhaustion and counts `pool_exhausted`; the redraw loop lives in the worker (D-O4).
- Fallback (A6): exemplar source fills the same pool with `source = 'exemplar'`; a KP with
  no approved template is flagged by a read-only query (`operator_flags`) that M5 exposes.
  No synchronous generation anywhere.
- A7 seam: `trait ProblemSource { fn fill(&self, kp, n, seed) -> Vec<Instance> }` with
  `TemplateSource` and `ExemplarSource`; a generator is a third impl in a later milestone.
- Claimed pool rows are kept (the served-instance log, A5); a retention job is M5's.
- Benchmarks (spec §10): A = core-only, deterministic, hard gate (p95 < 5 ms per
  instantiate+evaluate+hash+ring, plus an allocation-count bound); B = store round-trip
  against the CI Postgres (p95 < 100 ms, recorded as an artifact); the budget split is
  written in `docs/reference/l1-budget.md`.

## Units

| Unit | Deliverable | Acceptance check |

| U1 | `cadus_core::template`: document types (serde, deny_unknown_fields), constraint language + evaluator, renderer (scanner grammar), exact evaluator over the M2 AST with the function set, domain enumeration, `space_size`, seeded PRNG draws | the 1.0 template `a**2` over 1..12 renders `Compute $7^{2}$.` for `a = 7` with answer `49`; a constrained pair `a > b` never draws `a <= b` over 10,000 draws; `\times` as a choice value renders; a rational parameter draws reduced fractions |

| U5 | Benchmarks A and B, `docs/reference/l1-budget.md`, CI step after `cargo test` (serialized), artifact upload | A: p95 < 5 ms and allocation count under the literal bound; B: p95 < 100 ms on this box and on the CI runner |
