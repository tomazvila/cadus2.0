# Framework checklist

One row per audit finding of `docs/reviews/FRAMEWORK-audit-2026-09-06.md`, and one
row per required item and acceptance check of `ASSIGNMENT.md`. The plan that owns
the units is `docs/plans/FRAMEWORK.md`. The handover is
`docs/plans/FRAMEWORK-HANDOVER.md`; its section 7 is the completion pass this
revision reflects.

Column rules:

- **Implementation** — the commit(s) on `framework/completion-docs` that land the
  code. Commits before `699fa89` are the six units of the first swarm, merged at
  `4f6ddb1`. `—` means no commit.
- **Tests** — the test file that holds the evidence, with the test name where one
  test carries the row.
- **Content evidence** — the curriculum, report, or deployment artifact that shows
  the outcome on real content.
- **Residual limitation** — what the row does NOT establish after the work lands.
- **Status** — `done` when every other column is filled and the whole claim of the
  row holds on this branch. `open` when something the row needs is absent: content
  approval, the full gate, a browser run, staging, deployment, or code. `pending
  integration` when the code exists on a sibling lane and root cherry-picks it
  after this snapshot (handover §7.3); root replaces the marker with the hash.
