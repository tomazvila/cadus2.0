## Fixed decisions (orchestrator)

- All M3 code lives in `cadus-core`: modules `event`, `learner` (model), `config`, `fire`,
  `xp`, `projector`, `selector`, `numeric` (the Python-parity helpers). Allowed new deps:
  `chrono`, `chrono-tz` (tz database compiled in), `sha1`, `indexmap`. No network/DB/LLM.
- Wire shapes are the 1.0 shapes byte-for-byte (`docs/reference/event-schemas-1.0.json`):
  `deny_unknown_fields`; `repNum`/`memoryBase` camelCase; `ts` RFC 3339 with `Z`; `v` = 1
  and any other `v` is an error (1.0 `SHIMS` is empty); `type` is the discriminator.
- Floats: the fold uses `f64` with the 1.0 algorithms reproduced exactly (spec §7):
  Neumaier summation where 1.0 uses `sum()`, naive accumulation where 1.0 uses `+=`,
  round-half-even for `round()`, correctly-rounded decimal for `round(x, n)`, LIFO `_relax`
  with strict `>`. D6 (no floats in equality) binds the answer checker, not FIRe.
- Time: instants are UTC microseconds (`i64`); `days = Δµs / 86_400_000_000.0`; a naive
  `ts` is UTC; `local_day` uses `chrono-tz`; `now` is an explicit parameter; `built_from_ts`
  is excluded from every parity blob.
- Iteration: sort by topic id wherever 1.0 iterates a set; `IndexMap` where 1.0 relies on
  dict insertion order (`balances`, ability deltas: attempted topic first, then sorted).
- The 2.0 learner model adds `through_seq` (D4 cursor) OUTSIDE the parity blob; the store
  row `learner_models.through_seq` carries it.
- `attempt_id` rule (trap T12): `"{task_id}-{n}"`, `n` = 1-based attempt index within the
  task; the events unique index dedups; the fold uses it only for `apply_regrades`.
- Selector: ported with every ordering rule of spec §6; the quiz sampler runs behind a
  `QuizSampler` trait with 2.0's own seeded RNG (trap T11: the CPython `random.sample`
  sequence is NOT reproduced; recorded as a 2.0 change; the sampled ids go on `task_served`).
- Any change to the fold bumps `PROJECTOR_VERSION` (2.0 starts at 3 for parity and bumps
  to 4 on its first deliberate divergence).
