## Fixed decisions (orchestrator)

- Layering: `cadus-web` never depends on the model-client crate (L6 as a compile-time
  rule, unit U12); model calls run only in `cadus-worker` (R4, T2).
- The grade path is ONE transaction (D-O2): `begin_tenant`, load state, normalize +
  `check`, tier, `attempt_id = "{task_id}-{n}"` (`-rework` for H3), one `INSERT … ON
  CONFLICT DO NOTHING` (a zero-row insert IS `already_recorded`), incremental fold —
  full replay when the new events hold a `regraded` (1.0 `service.py:272`) — state
  write, distractor lookup, `diagnosis_jobs` enqueue for a miss without a pre-authored
  diagnosis, commit. Verdicts for numeric/expression kinds are decided for correct AND
  wrong answers (A3); multi-step/proof kinds get no deterministic verdict.
- T5 defaults on every model request: prompt caching on, reasoning max tokens set,
  provider order pinned for OpenRouter; the same client serves a local OpenAI-compatible
  endpoint through `OPENAI_BASE_URL`. T4 knobs exist with default 0 = unlimited (O2).
- T6: one `model_call_log` row per HTTP attempt with cached/uncached/output/reasoning
  tokens read from `usage` (0 when absent), latency, purpose, cost (NULL when unknown).
- Auth follows the M5 auth contract in `docs/SCHEMA.md`: the five SECURITY DEFINER
  lookups before the tenant bind; every write after it.
- Budgets per route in `docs/reference/l1-budget.md` (§8 of the spec); benchmarks A/B
  extend the M4 harness.
