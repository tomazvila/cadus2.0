# M0 — Workspace scaffold, schema v1, RLS proof

Requirement IDs: R1–R4, C2, C3, D9. Owner decision O1 default applies: keep the
`events` row shape of 1.0 so the migrator is a straight copy; build the migrator in M3.

## Fixed decisions (orchestrator)

- Workspace crates: `crates/core` (`cadus-core`), `crates/store` (`cadus-store`),
  `crates/web` (`cadus-web`, bin), `crates/worker` (`cadus-worker`, bin).
- Migrations: `migrations/NNNN_name.sql`, forward-only, run by `sqlx::migrate!()`.
- Gate: `scripts/gate.sh` runs `cargo fmt --check && cargo clippy --all-targets --
  -D warnings && cargo test`, then `cargo sqlx prepare --check` and
  `scripts/check_migrations.sh`.
- Test database: `CADUS_TEST_DATABASE_URL` points at a superuser DSN. Each test run
  creates a fresh database on that cluster, migrates it, and connects as `cadus_app`
  (trust auth) for RLS tests. Role creation is idempotent because roles are
  cluster-scoped.
- `events.payload` is `jsonb` (D7). Open finding for M3: 1.0 stored `json` because its
  diagnostic projection read key order. The 2.0 projector must not depend on key order.

## Schema v1 (D9)

| Migration | Tables |
|---|---|
| `0001_roles` | roles `cadus_owner` (NOLOGIN), `cadus_app` (LOGIN NOSUPERUSER NOBYPASSRLS), `cadus_admin` (NOLOGIN BYPASSRLS, member of `cadus_app`); extension `citext` |
| `0002_identity` | `users`, `auth_sessions`, `oauth_accounts`, `auth_tokens`, `auth_rate_counters` |
| `0003_event_log` | `events` (PK `(user_id, seq)`, partial unique `events_attempt_idem`), `learner_models` |
| `0004_scratch` | `profiles`, `session_plans`, `diag_states`, `user_settings`, `web_states`, `anki_queue`, `anki_cards_created`, `email_outbox` |
| `0005_content` | `content_store` (D-S4), `serving_pool` (D-S5), `model_call_log` (T6), `diagnosis_jobs` (D-S6) |
| `0006_grants_rls` | grants, default privileges, `REVOKE UPDATE, DELETE, TRUNCATE ON events FROM cadus_app`, `ENABLE` + `FORCE ROW LEVEL SECURITY` + policy `tenant_isolation` on every tenant table |

RLS-scoped tables (literal list): `events`, `learner_models`, `profiles`,
`session_plans`, `diag_states`, `user_settings`, `web_states`, `anki_queue`,
`anki_cards_created`, `serving_pool`.
Exempt tables that carry `user_id` (literal list, with reason): `auth_sessions`,
`oauth_accounts`, `auth_tokens` (looked up before a tenant context exists),
`email_outbox`, `diagnosis_jobs` (worker claims across tenants), `model_call_log`
(operator telemetry, nullable `user_id`).

## Units

| Unit | Deliverable | Acceptance check |
|---|---|---|
| U1 | Workspace scaffold, lints, `scripts/gate.sh`, core-purity test | `scripts/gate.sh` passes; purity test fails when `sqlx` is added to `crates/core/Cargo.toml` |
| U2 | Migrations `0001`–`0006` | All migrations apply on an empty database; a second run is a no-op; `cadus_app` cannot `UPDATE events` (checked with `psql`) |
| U3 | `cadus-store`: config, pool, `migrate()`, `assert_rls_enforced()`, `with_tenant()` unit of work, test support, RLS + append-only proof tests | Tests assert literal SQLSTATE `42501` on `UPDATE`/`DELETE` of `events` as `cadus_app`; cross-tenant `SELECT` returns `0` rows; boot guard rejects a superuser DSN |
| U4 | `cadus-web`: axum app, `/api/health`, `/api/ready`, boot guard wiring | `GET /api/health` returns `200` and body `{"ok":true}`; boot with a BYPASSRLS DSN exits non-zero |
| U5 | `cadus-worker` skeleton, CI workflow, `scripts/check_migrations.sh` | Worker starts, ticks, stops on SIGTERM; CI YAML validates; migration check passes |
| U6 | `Dockerfile`, `docker-compose.yml` (db + migrate + web + worker) | `docker compose config` validates; image builds |

Phase A runs U1 and U2 in parallel. Phase B runs U3–U6 in parallel after Phase A
merges. Every unit runs on Opus 5 in a worktree. Mutation check after Phase B: one
agent breaks the `REVOKE`, the `FORCE`, and the boot guard, and confirms the tests fail.
